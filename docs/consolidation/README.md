# Consolidation POC — evidence for the libforge / monorepo decision

This directory holds the artifacts of a one-day, reversible proof of concept
run on 2026-09-03 against the plan in `forge-poc-day-plan.md` (kept outside
the repo). Its purpose is to produce **evidence for a decision, not a
migration**: should each part of `libforge` come into this monorepo, and why?

Nothing here concludes the Notion RFC "Forge stack integration testing"; it
feeds that discussion.

| document | what it answers |
|---|---|
| `findings.md` | surprises, latent bugs, decisions that need a human, what a real migration would need |
| `cost-report-libforge-bump.md` | Experiment A: what a five-week-deferred library bump actually cost |
| `package-inventory.md` (+ `.json`, `-notes.md`) | Experiment B: per-package evidence for the in/out decision, generated by `tools/inventory` |
| `commands-move.md` | Experiment C: what broke when `commands/**` moved into the repo as its own module |
| `compat-validation.md` | Experiment D: making `compat.yml` runnable without cutting tags, with a provenance guard against vacuous passes, and what its first real runs found |
| `divergence-august-2026.md` (+ `.json`) | Experiment E: how often the mains actually diverged in August, generated by `tools/divergence` (reproducible byte for byte; the hand-written reading at the end is preserved across runs) |
| `polyrepo-august-casestudy.md` | Experiment E companion: the coordinated library↔service changes that actually happened in the live per-service repos in August, traced commit by commit |
| `forgeclient-divergence.md` | plan question 8: how far `ingot/forgeclient` and `ingot/tokenstore` drifted from `guppy/pkg/client` and `guppy/pkg/tokenstore`, hunk by hunk |
| `guppy-status.md` | plan question 6: is guppy functional against the current stack, with the version-pair qualifier |

Everything in this directory and under `tools/` is additive and
decision-neutral. The code changes on this branch (dependency bump, module
move) are demonstrations with measured costs, not proposals to merge.
